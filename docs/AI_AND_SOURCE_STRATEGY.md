## 推奨構成

自社の商品台帳と承認済み仕入先の構造化データを一次情報とし、文書検索と公開Web検索を補助に使う。コードが販売・価格・在庫・注文可否を判定し、モデルは質問分類を補助する。モデル停止時も社内の商品検索と受付は利用可能にする。

| 選択肢                      | 長所                                          | 制約・用途                                                                        |
| --------------------------- | --------------------------------------------- | --------------------------------------------------------------------------------- |
| Excel/CSVの正規化＋型番検索 | 社内データを正確に照合しやすい。API利用費不要 | 更新頻度は運用に依存。表の見出し・型番文字列・公開価格と原価の区別を管理          |
| 仕入先API/CSVとの同期       | 指定項目を決まった形式で更新できる            | 仕入先ごとの認証・契約・API仕様が必要。万能な汎用ログインは作らない               |
| カタログ文書検索            | PDFやWordにしかない仕様を検索可能             | 仕様記載と現在の販売可否は別。画像PDFはOCR後に取り込む                            |
| Exa/Tavily検索              | 未登録の商品・メーカーを探す用途              | APIキーと利用料、サイト情報の鮮度・誤一致に注意。検索結果を取扱承認に昇格させない |
| Geminiの構造化抽出          | 自然な日本語から問い合わせ意図を抽出          | スキーマが正しいことと判断が正しいことは別。コードで再検証する                    |
| JevのChoice分類             | 既知の選択肢への振り分け、信頼度による見直し  | 検索/カタログ取得/文章生成は別途必要。小さく定義した判断に使用                    |
| ブラウザー操作エージェント  | APIがない一部の仕入先画面への将来対応         | ログイン、画面変更、二重注文への対処が必要。標準コネクターと分離して個別検証      |

## Jevについて

ユーザーが指すJevはTypeSafe AIのSystem Oneモデル。公式資料は、状態と型付き質問から選択肢・スコア・確率等を返すモデルとして説明している。今回の適用範囲は「価格照会か、在庫照会か、製作相談か」などの限定した分類。分類結果があっても、登録データ・機能フラグ・販売承認・注文条件を飛ばせない。

実装するHTTP接続は公式の `https://api.typesafe.ai/v1/systemone`。モデル名は管理画面で変更可能。Jev未設定時はローカル分類へ戻る。日本語の工業製品問い合わせでの優劣は未評価であり、採用モデルが決まったと断定しない。

## 接続後の評価手順

実際の匿名化した問い合わせを、取扱/類似型番/数量/価格/在庫/製作/情報なしに分けて50件程度用意する。正解候補と「回答を保留すべき条件」を社員が確認する。local、Jev、Geminiで、型番取り違え、誤った販売可否、保留判断、応答時間、API費用を比較する。販売可否の誤断定を優先して減らす。

実API鍵が未提供の開発段階では、外部APIの入出力をモックで検証する。ライブAPIの品質やコストの比較は実施済み扱いにしない。
