# チャットの会話・表示改善（2026-10-03）

## 依頼と原因

「いつぐらいに届く？」に商品未確認の回答が返り、商品カードと入力欄が会話を圧迫していた。確認時の管理設定は `decisionProvider=local`、Gemini/Jev/外部検索のAPIキーは未設定。

納期判定が「納期」「いつ届」「何日」等の狭い表現に限られ、「いつぐらいに届く」を拾えていなかった。納期質問と判定できないため、直前の商品を参照する処理にも入らなかった。API未接続に加え、アプリ側の文脈処理に修正が必要な状態だった。

## 変更内容

- 「いつぐらいに届く」「いつ頃届きますか」「何日かかる」等を納期として扱う。
- 直前の商品を保持して価格・在庫・納期に回答。質問に対する情報を本文で直接伝える。
- 商品候補が複数なら確認し、「2番目」やメーカー名で絞り込む。新しい未登録型番の質問後に以前の商品へ勝手に戻らない。
- 商品をまだ指定していない納期質問には、商品名・型番を尋ねる。
- あいさつ、お礼、数量への回答を扱う。「価格は？ → 10個くらい欲しい」は登録単価から税抜・送料別の商品代金目安を計算する。
- 特定の商品名に一致した場合は、同じ大分類に属するだけの別商品を候補から除く。
- 外部の意図抽出に直近6メッセージの文脈を渡す。抽出した型番は最新の質問内に存在するものに限定する。
- 過去の会話を開き直す際も、商品の最新状態・価格等の公開設定を使って事実を含む本文を再構築する。
- `ChatMessage` に `intent`, `presentation`, `requestedQuantity` を任意項目として追加。既存DBを破壊する変更はない。

## 表示の設計

| 画面幅（CSS px） | 表示                                                                                |
| ---------------- | ----------------------------------------------------------------------------------- |
| 1200以上         | 幅400pxのチャットを右側の専用領域に配置。ページ側の幅を縮め、相談フォームと重ねない |
| 761〜1199        | 幅400pxのモーダル。背面を操作不可にし、背面の相談フォームを一時的に隠す             |
| 760以下          | 全画面の会話。動的ビューポート、キーボードによる高さ変更、セーフエリアを考慮        |

- ヘッダー／スクロールする会話／入力欄をCSS Gridの別領域に配置。入力欄は会話の上に重ねない。
- チャットを開いている間は、すべての画面幅でトップの相談フォームを非表示にする。PCではその空白も詰めて会社紹介を表示し、チャットを閉じると入力内容を保持してフォームを戻す。
- 商品カードをコンパクトにし、詳細情報を折りたたむ。続きの回答でカードを繰り返さない。
- 質問候補は最新の回答にだけ表示。参照元は折りたたむ。
- 入力欄は内容に合わせて伸び、最大104px。送信状態、再試行、最新位置への移動、新しい相談を用意。
- 会話領域だけをスクロールし、背面ページが勝手に移動しないようにする。
- 小さい画面ではフォーカスを会話内に保ち、閉じると元の操作箇所に戻す。PCの専用領域ではページ操作も継続できる。

参考にした公式の画面・設計資料:

- [Intercom公式サイト](https://www.intercom.com/): ブランドサイトとサポート導線の関係。
- [Intercom Messengerのカスタマイズ](https://www.intercom.com/help/en/articles/6612589-set-up-and-customize-the-messenger): ヘッダー、会話開始、メッセージの構成。
- [Intercom Messenger FAQ](https://www.intercom.com/help/en/articles/6612597-messenger-faqs): ランチャーの位置、余白、表示方法。
- [Zendesk Web Widget公式資料](https://developer.zendesk.com/documentation/zendesk-web-widget-sdks/): 埋め込み式の会話体験。

専用領域を確保してページを縮める方式は、今回の「相談セクションと重ねない」という要望に合わせた独自の判断である。

## AI接続についての引継ぎ

**2026-10-06更新:** 以下は10月3日時点の状態。現在は回答生成コードを追加済みで、APIキーの設定と実接続確認が残っている。最新の仕様と操作は [AI接続手順](AI_SETUP.md) を優先する。

現在の応答は、改善した検索・会話ルールと登録情報から作られる。生成AIが自由な文章を生成していると表示しない。

既存のGemini/Jevアダプターの役割は質問意図の抽出・分類である。今回、会話履歴をその入力に追加した。APIキーが未提供のため、この変更は模擬応答で契約を検証した。キーを設定するだけで自由な文章生成に切り替わる実装ではない。

自由な文章生成まで希望する場合は、別途Gemini等の生成層を接続し、会社の根拠データに基づく応答を実問い合わせで評価する。価格・在庫・販売承認・注文処理は引き続きサーバーで確定し、生成モデルの判断だけで変更しない。
