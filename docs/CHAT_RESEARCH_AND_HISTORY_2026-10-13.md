# 見積への誘導、前回の相談の整理、担当者向けAI調査（2026-10-13）

## 依頼

- お客様がより買いやすくなるように誘導する。1つの会話で電話番号を何度も出さない。冗長な内容を避ける。
- しばらく空けて戻ったとき、前回の相談が見にくく邪魔にならないよう、消すかアーカイブする。保存でサイトのDBに負担をかけない。
- 価格の見積、発送・到着の期間を、担当者がブラウザで調べる代わりにAIで調べる。判断もAIで行う。お客様役のエージェントを作り、そこを中心に会話を試験する。

確認のうえ、次のとおり決めた。

- AIの調査結果は担当者向けメモにだけ残し、お客様には表示しない（通販価格を見せると他で買われるおそれがあるため）。
- 調べる情報源は、メーカー公式サイト・カタログ、通販サイト、運送会社の日数・送料表、登録済み仕入先のサイトの4つ。
- 調査のAIは、OpenAIとJevの最新情報を調べて選ぶ。トークン単価の安いJevをできるだけ使う。
- 最後のやり取りから12時間で新しい相談にし、前回分は一覧から開けるようにする。保存先はサイトのDB以外にする。

## OpenAIとJevの選択

2026年10月時点の公式情報で比較した（料金は変わることがある）。

| 項目           | Jev（TypeSafe System One）                                                                  | OpenAI                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| できること     | 選択肢から選ぶ・yes/noの確率・基準に沿った点数。文章生成・Web検索・数値の抜き出しはできない | Web検索とページの読み取り、決まった形式での出力                                        |
| 料金           | 入力100万トークンあたり0.042ドル、出力は無料                                                | Web検索1回0.01ドル＋トークン料金（gpt-5-mini: 入力0.25ドル・出力2ドル／100万トークン） |
| 向いている用途 | 分類・振り分け・確認（公式資料の使い方：一度に多数の判定、信頼度による振り分け等）          | 調べる・読む                                                                           |

Jevだけでは調査できないため、役割を分けた。

- **Jev（判断）**：調査が必要か（購入の情報を求めているか、品目を特定できるか）と、調べる項目（価格・在庫・納期・送料）を判定する。見つかった各ページが、その品目（送料なら配送条件）に当てはまるかも判定する。1回の判定で複数の質問をまとめて問う。
- **OpenAI（調査）**：Web検索で調べる。検索モデルは `gpt-5-mini`（`gpt-4.1-mini` は調べるサイトの指定に対応していないため）。

1回の調査で使う量の目安：OpenAIの検索が2回（一般の検索と、仕入先サイトに絞った検索）で約0.03ドル、Jevの判定が2回で0.0001ドル未満。

活用事例の調査では、購買の見積比較・調査にAIを使う例は増えている。一方で、誤りの混入（ハルシネーション）や情報漏えいへの対策として、人の確認を前提に段階的に導入する例が中心だった。今回の「担当者メモのみ」の方針はこれに合う。

## 変更内容

### 1. 見積への誘導と簡潔さ

- 価格・在庫・納期・見積・注文・値引き・送料・支払の質問は購入の意思とみなし、回答の下に「この内容で見積を依頼する」ボタンを出す。
- 登録商品の価格を答えた直後には、「数量とご連絡先だけで正式なお見積りを依頼できます」を一度だけ添える。
- 電話番号は1つの会話で1回だけ案内する。2回目以降は、電話番号を添えるだけの文を省く。お客様が電話番号・営業時間を尋ねたときは改めて答える。
- 会社の電話番号・FAXの質問に答える。
- 生成AIへの指示を「2段落・180字程度、お客様の条件を並べ直さない、見積に足りない情報を1つか、そろっていれば見積依頼できることを添える、押し売りしない」に変えた。
- 担当者への案内文を短くした。

### 2. 前回の相談の整理

- 最後のやり取りから12時間たつと、次に開いたときは新しい相談として始まる。
- 前回分はお客様のブラウザ（localStorage）に保存し、チャットの「過去の相談」ボタンと、最初の画面の「前回の相談を見る」から閲覧のみで開ける。保存は最大10件・30日で、1件ずつ、またはすべて削除できる。
- サイトのDBには追加の保存をしない。現在の会話は従来どおりサーバーに保存され、担当者が確認できる。

### 3. 担当者向けのAI調査

管理画面の機能オプション「AIによる価格・納期の調査（担当者向け）」をオンにすると、価格・在庫・納期・送料を聞かれた未登録の品目を、回答を返した後に調べる。お客様の待ち時間は増えない。

1. Jevが、調査が必要かと、調べる項目を判定する。
2. OpenAIがWeb検索で、メーカー・通販サイト・運送会社（北九州発→お届け先）を調べる。分野が一致する登録済み仕入先のサイトも、サイトを指定して調べる。
3. このサーバーが出典ページを開き、記載を照合する。結果は4通りで表示する。
   - ページで確認済み（金額・日数は単位ごと、寸法などは数値として、すべてページにある）
   - 一部のみ確認（数値の一部だけ、または「翌日」「在庫あり」のような短い語だけがある）
   - ページの記載と不一致（AIの読み違いの可能性が高い）
   - 自動取得できず未確認（サイトが自動取得を拒否している）
4. 検索で訪れていないサイトのURLは、AIが作り出したものとして捨てる。
5. Jevが、各記載がその品目（送料なら北九州発・お届け先までの区間）に当てはまるかを判定し、一致度を表示する。ページにお客様の型番・サイズが見当たらない記載と、一致度50%未満の記載には「別の型式・サイズの可能性」と表示する。

結果は管理画面「相談・引継ぎ」の会話の詳細に「AI調査メモ（担当者用・お客様には表示されません）」として表示する。見積依頼から来た場合は、管理画面「見積」の明細編集にある「チャットの会話とAI調査メモを見る」からも開ける。調査は1つの会話で3回まで。同じ品目の説明が増えただけのときは調べ直さず、新しい項目・お届け先・数量が加わったときだけ調べる。登録商品で価格と納期が登録済みなら、送料だけを調べる。確認用（デモ）の商品は調べない。

ボット対策のあるサイトは自動取得を回避せず、「未確認」として担当者に確認を委ねる。試験ではモノタロウとミスミがこれに当たった。

仕入先サイトを調べるため、該当する仕入先のドメインをOpenAIの検索条件として送る。社名・URLがお客様に出ることはない。

### お客様役エージェントによる会話試験（1回目）

試験用サーバー（本番と同じコード、OpenAI・Jevの実API、AI調査オン）で、3種類のお客様役エージェントがそれぞれ3会話・各5〜7往復を行い、回答と担当者メモを評価した。メモの出典は実際にページを開いて値を確かめた。

| エージェント | 役柄                             | 品目の例                                                                       |
| ------------ | -------------------------------- | ------------------------------------------------------------------------------ |
| u1           | 急ぎの設備保全担当（話し言葉）   | 三ツ星Vベルト B60、NSKベアリング 6205DDU・6305ZZC3、ニチアス トンボNo.1995     |
| u2           | 他社と比較する購買担当（丁寧語） | キッツ ボールバルブ UTKM 20A、ガスケット＋SUS304ボルト、DEMO-CAST-01＋SUS304板 |
| u3           | 仕様から相談する設計担当         | 炉の断熱ブランケット、炉の覗き窓ガラス、SUS316金網トレー                       |

良かった点：電話番号は各会話0〜2回に収まり、見積依頼のボタンは毎回出て押し付けがましくなかった。最後の要約は途中の訂正も反映していた。担当者メモには通販価格・出荷目安・運賃表の手がかりが多く、出典の多くは実際に一致した。

見つかった問題（お客様向け）：

- 「注文」「見積」という語だけで手続きの定型文に振り分けられた。「今日注文したら最短いつ出荷？」に「ご注文を受け付けていません」、見積の回答時期の質問に見積の手順が返った。
- 「ご案内できるのは取扱分野までのため…」「お支払い方法・条件は…」などの定型文が毎ターン入り、同じ趣旨の段落が二重になった。
- 用途の「ポンプのモーター」を品目と取り違えた。「ジョイントシート」を継手として扱った。鋳物部品の後に聞いた「SUS304の板の1枚の価格」に鋳物部品の単価で答えた。
- 「B60」を型番と認識せず、伝えたメーカーを聞き返した。未登録の型番に「取扱いを確認できませんでした」で始めた。
- 本文の「この内容で見積を依頼する」と、表示されたボタン「この内容で担当者に相談する」が食い違った。
- 「社内で加工か、外注か」の質問に仕入先の非公開の定型文が2回続き、本題（二重窓の構成）に答えなかった。
- 営業時間、見積の回答までの日数、送料無料の基準、引き取りの可否に答えられなかった。
- 生成文が自社を「御社」と呼んだ、「facts」という語を出した、急いでいないお客様に「お急ぎのご注文」と書いた、電話番号を消した結果「急ぎの場合はへお電話」と壊れた。

見つかった問題（担当者メモ）：

- 発送元の「北九州から」を届け先と判定し、送料・日数を北九州→福岡で調べた。
- 「1本いくら」の「1本」を数量と読んだ。
- 実在する値（「600×1200」「目開き2.58mm・開口率66.0%」など）を「不一致」と判定した一方、関東発の運賃表や、別型式（外パッキンと内パッキン、10UTMとUTKM）の値を「照合済み」とした。
- 要約に「別の販売サイトでの検索を許可ください」のような依頼文が入った。
- 用途の「ポンプ」でポンプの仕入先サイトを調べた。登録商品（確認用）が会話に出ていると、別の未登録品の調査をしなかった。
- チャットの「この内容で見積を依頼する」から送った見積依頼に、会話の記録とAI調査メモが紐づいていなかった（問い合わせには紐づいていた）。

### 1回目の結果を受けた修正

- 振り分け：「注文したい」「見積をお願いします」のような依頼だけを手続きとして扱う。「注文したら」「見積を依頼した場合」「依頼するか決めます」、否定された語（「在庫の話ではなく」「注文じゃなくて」）は質問の中身で答える。「まとめての発注」を要約の依頼と誤認しない。「12月20日の据付に間に合わせたい」を据付工事の依頼と扱わない。
- 新しい決まった回答：見積の回答時期、見積に書く項目、ボタンで会話が伝わるか、引き取り、社内加工か協力会社か。営業時間・見積回答の目安・送料・引き取りは、管理画面の「よくある質問への回答」に書けばその文を案内する（空欄なら担当者が確認すると答える）。
- 決まった文は会話中1回。同じ質問が続いたら、生成AIがその要点を短く言い換えて会話の流れで答える。補足では、決まった文の言い換えや「担当者が確認します」「見積を依頼できます」の繰り返しを省く。
- 品目：ベアリング・Vベルト・ボルトの確認項目を追加。「ポンプのモーター用」「用途はポンプ」の語は品目として扱わない。「ジョイントシート」はパッキン。前の登録商品と別の品目を聞かれたら前の商品の価格で答えない。
- 型番：「B60」「6205DDU」「6305ZZC3」を型番として扱い（ねじの呼びM16、寸法W600、合金A5052、鋼材S45Cは除く）、訂正された長い型番を優先する。未登録の型番は「登録商品にはありませんが、お取り寄せを含めて担当者が確認します」と答え、伝え済みのメーカー名・数量は聞き直さない。
- ボタン：見積依頼のボタンを一度出したら出し続ける。本文のボタン名を表示中のボタン名に直す。「電話で話したい」には電話番号を先に案内する。
- 生成文の検査：入力の項目名、「御社」「貴社」、お客様が言っていない「お急ぎ」、根拠のない加工・施工の対応を拒否して書き直させる。電話番号の2回目以降は文ごと省く。
- 担当者メモ：お届け先（発送元を除く）、数量（書かれたとおり、単価の言い方を除く）、照合（単位付きの金額・日数、数値、短い語は「一部のみ確認」）、「別の型式・サイズの可能性」の表示、依頼文を除いた要約、品目の分野による仕入先の選択、登録商品と別の品目の調査。
- 見積依頼に会話IDを保存し、会話を「担当者に引継ぎ済み」にする。管理画面「見積」から会話とAI調査メモを開ける。

### OpenAIのクレジット切れ（試験中に発生）

2回目の試験を始めた直後の02:58頃、試験に使っていたOpenAIアカウントのクレジットが尽き、APIが `insufficient_quota`（You have no credits remaining）を返すようになった。以後、生成AIの回答はすべて決まった文と組み立て文に切り替わり、担当者向けのAI調査はHTTP 429で失敗した。Jev（TypeSafe）は動作を続けた。

この間、チャットは1回ごとにOpenAIの失敗の返事を約6秒待ってから切り替えていた。また、管理画面にはそのことを知らせる表示がなかった。次の対策を入れた。

- OpenAIが残高不足を返したら、10分間はOpenAIを呼ばずに、すぐ登録情報と決まった文で回答する（待ち時間をなくす）。AI調査も止める。
- 利用記録に `insufficient_quota` として残し、管理画面の概要に「OpenAIの利用残高が不足しているため、生成AIによる回答と担当者向けのAI調査が止まっています」と表示する。調査メモにも理由を表示する。

1回目の修正後、同じ3種類の役柄で2回目を行った（各3会話・7往復前後、1回目の結果は見せずに実施）。開始直後にOpenAIのクレジットが尽きたため、AIが動いていたのは2会話（r1-a、r2-a）と、r3-aの前半だけだった。

| 評価項目（会話ごと）    | 1回目（AIあり、9会話） | 2回目・AIあり（2会話） | 2回目・AI停止中（7会話） |
| ----------------------- | ---------------------- | ---------------------- | ------------------------ |
| 質問への答え            | 悪い6・普通3           | 普通2                  | 悪い7                    |
| 見積までの流れ          | 普通8・悪い1           | 良い2                  | 普通4・悪い3             |

| メモの有用性            | 良い2・普通5・悪い2    | 良い2                  | 調査失敗のため評価不能   |

AIが動いていた2会話では、本文の案内とボタン名が全回一致し、見積依頼まで迷わず進めたと評価された。注文の言い回しで「注文受付休止」が出る問題、支払条件などの定型文の繰り返しは出なかった。残った指摘は、決まった文のあとにAIが同じ内容を言い換える重複（その後、言い換えの文を省く処理を追加）、伝えたメーカー名の聞き返し（その後、メーカー名は聞かないよう変更）、「何時までに頼めば当日発送？」への営業時間の回答（その後、当日出荷の締め時刻として回答）だった。

AI停止中の7会話は、2回目開始時点のコード（下記の追加修正の前）での評価になる。AIがないときの組み立て文で次の不具合が見つかり、修正した。

- 決まった文を省いた結果、AIも使えないと本文が空になる（5回）。→ 本文が空にならないよう、省いた文を戻す・最後に必ず文を入れる処理を追加。
- 「℃」が正規化で「°C」になり、温度を伝えても「まだ伺っていない温度」と聞き返す。→ どちらの表記も温度として扱う。
- 要約と見積フォームの下書きが直近8文だけで、最初に伝えた品目・数量・届け先が落ちる。苦情の文や「まあいいや」が入る。→ 最初の文と直近の文を残し、型番・条件・数量（最新の値）・届け先を「伺った条件」として先頭に入れる。苦情や相づちは除く。
- 「40個から60個に」で40個、「1個あたり8,400円？」で1個と読む。→ 最新の数量を使い、単価の言い方は数量にしない。単価の確認には単価で答え、前に話した登録商品へ戻る。
- 「値引きの件は承知しました」で値引きの定型文が出る、「送料はいくら？」に価格の定型文が出る。→ 了承の文と送料の質問を区別。
- 品目を伝えても「どの商品か」と聞き返す。確認用の鋳物部品の分類（耐熱ガラス・鋳物）から要約がガラスの確認項目になる。→ 伝えた品目で答え、登録商品は商品名から品目を判定。
- AIの残高切れの間、毎回約6秒待ってから組み立て文になる。→ 前述の一時停止で待ち時間をなくした。

## 運用上の注意と残る課題

- OpenAIのクレジットを追加するまで、生成AIの回答と担当者向けのAI調査は止まったまま（チャットは登録情報と決まった文で回答を続ける）。追加後に、AIありでのお客様役の試験をもう一度行う必要がある。
- 営業時間・見積回答の目安・送料・引き取りは、管理画面「設定」の「よくある質問への回答」に入れるまで「担当者が確認します」と答える。
- 調査機能は既定でオフ。有効にすると、調査1回あたり約0.03ドルのOpenAI利用料がかかる。今回は試験の途中でクレジットが尽きた。本番では利用状況（管理画面「AI利用記録」）と残高を確認しながら使う。
- 照合は「数値がページにあるか」までで、同じページの別の表（例：別の発地の運賃表、別のサービスの料金）の数値を「確認済み」とすることがある。品目の一致度と出典の確認が必要。
- 担当者メモの値は、照合済みでも、品目の型式やサイズが違う場合がある（一致度とnoteを確認する）。通販価格は仕入値でも販売価格でもない参考値である。
- 送料はサイズ・重量で決まるため、運送会社の料金表から目安を拾うまでにとどまる。会社の契約運賃は反映していない。
