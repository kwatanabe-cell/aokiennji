# ローカル処理・Jev・回答生成AIの役割

2026-10-06。「分かっている情報はローカルで処理し、必要な場面だけAI APIを使う」という追加要件の実装基準。

「ローカル」は、このアプリのサーバーと登録DBによる処理を指す。利用者のブラウザー内で判断することや、別のローカルLLMを起動することではない。

## 処理順序

1. 現在の公開設定、承認、情報の鮮度と、直前の会話を取得する。
2. ローカルで明示的な質問意図を複数抽出する。価格＋納期などを一項目に潰さない。
3. `planChatRoute` で分類API・文章生成・Web検索の必要性を決める。
4. 必要なときだけJev等を呼ぶ。明示的な価格・在庫・納期等の意図を、モデルの別分類で上書きしない。
5. 商品・分野を確定し、価格等の事実の本文をローカルで作る。曖昧・未承認・期限切れなら保留する。
6. 用途等の相談に必要な公開可能情報を回答生成AIへ渡す。価格・在庫・納期・販売可否の項目を生成用の商品データには含めない。
7. 事実と相談が混在する場合、確定本文を先に送信する。AIの検査済みの補足を連結し、確定本文をAI出力で置き換えない。
8. 会話を保存し、振り分け理由・実際に利用した方式・処理時間を監査履歴へ記録する。

過去の会話や公開資料に金額等が書かれている場合でも、それを生成AIが販売価格の根拠に昇格させることは禁止する。本文生成に渡す資料は参考資料である。AIの出力検査でも金額・在庫数等の生成を拒否するが、文字列検査だけで意味の正しさを完全には検証できないため、実問い合わせによる評価は接続後に行う。

## 実装の基準

- `lib/chat-policy.ts`: 質問意図の共通定義、処理の振り分け、理由コード。API使用の判断はここに集約する。
- `lib/server/providers.ts`: ローカルの意図判定も上記の共通定義を使用。Jev等は意味の解釈を補助する。
- `lib/server/chat-replies.ts`: 数量計算・複数の事実質問の回答を生成する。
- `lib/server/chat.ts`: 前後の会話と照合結果から方針を適用し、確定本文と生成補足を連結する。
- `lib/server/ai-responses.ts`: `businessFactsOwnedLocally=true` により、相談部分に限定した指示・出力検査を行う。
- `ChatMessage.factualIntents`: 回答した事実の項目を保存する。再読込時も公開設定の変更を適用し、過去の価格等を隠せる。
- `chat.routed`: 操作履歴の項目。理由コード、分類方式、回答方式、外部検索の利用、所要時間を記録する。APIキーや非公開資料の原文は記録しない。

管理画面の「設定」→「ローカル処理とAIの使い分け」で役割を確認できる。「操作履歴」では個別の会話が実際にどの経路で処理されたかを確認できる。

## 変更時のテスト

- APIキーが設定済みでも、明確な登録情報の照会では外部通信ゼロ。
- 型番のない登録商品名、複数質問、数量計算、候補選択でもローカル処理。
- 登録商品の用途相談では、Jevを省略して生成APIだけを呼ぶ。
- 曖昧な品目の価格照会では、Jevで分野を識別しても、価格回答はローカルの確認案内。
- AIが間違った金額を出しても、途中表示・最終本文に採用しない。確定価格は保持。
- 公開設定変更後の履歴でも、以前の数値を表示しない。
- 管理画面の役割説明、SSEによる途中表示、既存の会話・見積・注文フローが動く。

主なテストは `tests/chat-policy.test.ts` と `tests/ai-chat.test.ts`。APIキーの保存・実接続確認は [AI接続手順](AI_SETUP.md) を参照する。
