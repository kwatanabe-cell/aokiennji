## 4. ローカルにしかないものの移行

設定はテキスト2ファイルの内容をコピーすればよい。既存データも維持する場合だけ、DBをファイルとして移す。

| ノートPCのコピー元                                       | デスクトップの保存先                            | 必要性・移し方                                                                                                                       |
| -------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| プロジェクト直下の `.env.local`                          | cloneしたプロジェクト直下の `.env.local`        | 必須。ファイルの内容全体をコピーし、改行・引用符・`\$` などをそのまま保持する。AIキー・管理認証・SESSION_SECRETを引き継ぐ            |
| プロジェクト直下の `.local-admin.txt`                    | cloneしたプロジェクト直下の `.local-admin.txt`  | 同じ管理パスワードを使うならコピー。ログイン時に参照するメモで、アプリが読む設定ファイルではない                                     |
| `.data/migration/manual-copy-2026-10-15/aokienji.sqlite` | cloneしたプロジェクトの `.data/aokienji.sqlite` | 登録済みの仕入先情報・設定・相談履歴を維持する場合に必要。**バイナリなので、内容をテキストとしてコピペせずファイル自体をコピーする** |

DBのコピー元は2026-10-15にSQLiteのバックアップAPIで作成し、整合性を確認したファイル。WALの未反映データも含むため、このファイル1個で移せる。新しい端末のアプリを起動する前に配置する。バックアップ作成後にノートPCでデータを変更した場合は、作り直してから移す。

その他の扱い：

- ソース、画像、フォント、テンプレート、依存の定義、文書はGitHubから取得する。
- `node_modules`、`.next*`、テスト出力はコピーせず、新しい端末で再作成する。
- `.data/verification/` は過去試験の回答・評価・画像・シナリオ。通常の開発再開には不要。同じ台本の再評価や過去回答の比較をする場合だけ、必要な資料を別途コピーする。
- `.vercel/project.json` はVercelの同じプロジェクトを操作するときのみ必要。手動コピーするか、新しい端末でプロジェクトを紐付け直す。
- ブラウザのlocalStorage・Cookieは自動移行されない。管理画面は再ログインする。DBをコピーすればサーバー側の会話は維持されるが、ブラウザの「過去の相談」一覧は別の保存先なので移らない。
- Orga、GitHub、Linear、Vercel等の端末認証は新しい端末で行う。

設定の値と社内DBはGitHubやLinearへ載せず、端末間で直接移す。先に作った `.data/migration/desktop-2026-10-14/` のアーカイブは予備のバックアップとして残すが、今回の移行方法では転送不要。内部の引き継ぎMDは10月14日時点の内容なので、**GitHubへ保存するこのMDを優先する。**

## 5. デスクトップでの復元・起動

以下はLinux/macOS/WindowsのWSL等のBash用。確認済みのノートPC環境は **Node.js v24.12.0、npm 11.6.2、Next.js 16.3.8**。Node 24系とGitを用意する。Orgaの製品固有の操作・Linear連携は今回設定しておらず、IDEとして取得したプロジェクトを開けば作業を再開できる。

1. デスクトップでGitHubの `main` を取得する。初めて取得する場合：

```sh
git clone https://github.com/uta-s-dao/aokiennji.git aokienji
cd aokienji
```

すでにclone済みで、その作業フォルダの `main` にローカル変更がない場合：

```sh
cd aokienji
git status --short --branch
git switch main
git pull --ff-only origin main
```

ローカル変更がある場合は先に保存し、既存の作業を上書きしない。`git rev-parse HEAD` でノートPCのpushしたコミットと一致することを確認し、`docs/DESKTOP_HANDOFF_2026-10-14.md` を開く。

2. 第4節の2つのテキストファイルを作り、ノートPCから内容をコピーする。DBも継続する場合は `.data` フォルダを作ってバックアップファイルを `.data/aokienji.sqlite` に配置する。
3. プロジェクト直下で以下を実行する：

```sh
chmod 600 .env.local .local-admin.txt
npm ci
npm run typecheck
npm test
npm run dev
```

4. `http://localhost:3000` と `http://localhost:3000/admin` を開く。パスワードは `.local-admin.txt` を自分の端末で確認する。
5. 復元した設定を使うため、通常 `npm run setup` は不要。設定を移さず新規作成する場合のみ使う。既存 `.env.local` はsetupで上書きされない。
6. `.env.local` の `DATA_DIR=.data`、`APP_ORIGIN=http://localhost:3000` を確認。ポートを変えるならAPP_ORIGINも合わせる。デモで再開する際は `DEMO_MODE=true`、`ALLOW_LIVE_ORDERS=false` を維持する。

現在の通常DBは商品6件、情報源2件、仕入先知識41件、会話12件、メッセージ66件。回答生成は既定のローカル回答、AI調査はオフ、FAQは未設定。**APIキーがあるだけでは生成AIは有効にならない。** 管理画面「設定」で「OpenAIの構成を選ぶ（推奨）」→保存→接続確認を行う。

通常DBにはまだ `research_notes` テーブルがない。アプリがDBを初期化する際に `CREATE TABLE IF NOT EXISTS` で追加されるため、起動前の読み取り確認で存在しなくてもDBを削除・再作成しない。DBを移さない場合は、デモデータのみ新規作成され、既存の仕入先知識・設定・相談は復元されない。

Jevの現設定は `TYPESAFE_API_BASE_URL=https://ai-gateway.vercel.sh/typesafe`。過去の401について古いVercel資料だけで判断せず、[10月7日の接続先修正](VERCEL_JEV_FIX_2026-10-07.md)を参照する。`.env.local` 内のVercel OIDCトークンは期限や端末に依存するため、新しい環境でのログインの代わりには使わない。

追加の検証：

```sh
npm run build
npx playwright install chromium
npm run test:e2e
```

E2Eはポート3210、`/tmp/aoki-eng-e2e-*` の独立DB、PC・モバイルのChromiumで動く。通常DBや実APIキーは使わない。ブラウザの依存パッケージが不足する環境ではPlaywrightのエラーに従いOS側も準備する。
