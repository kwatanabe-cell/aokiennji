# お客様向けチャット：実APIによる試験結果

2026年10月7日（日本時間）。3つの独立した質問担当エージェントが13会話・60問を実チャットへ送信し、回答全文、継続質問、応答速度を確認した。さらにPCとスマートフォンの実画面で各2問、計4問を操作した。

**結論：OpenAIの実回答と画面動作は確認できたが、会話を最後までスムーズに進める品質には達していない。TypeSafe/Jevは認証エラーのため、両APIが正常に動く状態での試験は未完了。**

| 対象 | 実際の結果 |

| OpenAI | HTTP 200。`gpt-4.1-mini` の接続・応答形式確認に成功 |
| TypeSafe/Jev | HTTP 401。`jev-latest` による分類成功は0件。ローカル分類へ戻った |
| キー設定 | 両環境変数の値が完全に同じことを、値を表示せず確認した |
| 試験用サイト | `http://localhost:3212`。本来の設定・DBを複製した別環境 |
| 試験用設定 | 意図判定Jev、回答OpenAI。キーは `.env.local` から読み込み |
| 登録情報 | 非公開仕入先41件の情報を含む既存DBの複製。商品価格・在庫は確認用デモ情報 |
| 注文・送信 | 実注文・メール送信なし。外部Web検索なし。AI APIへのリクエストは実行 |

`TYPESAFE_API_KEY` にはTypeSafeで発行した専用キーが必要。同じキー値とHTTP 401は確認済みだが、キー発行元のアカウント状態までは確認していない。専用キーへの更新後、接続試験と同一シナリオによる再試験が必要。

元DBの意図判定設定は `local` のまま。今回API利用へ切り替えたのは試験用DBのみであり、普段のサイトに設定を適用したという意味ではない。

## 3エージェントの評価

判定は担当エージェントによる回答内容の評価。人間のお客様による利用評価や、HTTP成功率ではない。「良好」は質問に直接答えて次へ進める、「一部」は安全だが案内・文脈が不足、「改善必要」は質問に答えない、既知の条件を聞き直すなど。

| 質問担当 | 主な観点 | 質問数 | 良好 | 一部 | 改善必要 |
|---|---|---:|---:|---:|---:|
| 技術相談 | 用途からの選定、温度・寸法、材質、図面製作 | 20 | 5 | 6 | 9 |
| 会話の継続 | 価格・在庫・納期、数量計算、全角・ひらがな、話題変更 | 20 | 8 | 4 | 8 |
| 非公開・手続き | 仕入先情報、未知型番、見積、注文、担当者への相談 | 20 | 9 | 3 | 8 |
| 合計 | 13会話 | 60 | 22 | 13 | 25 |

60問のうちOpenAIの生成回答を採用したのは26問。生成を試みてから定型文へ戻ったのは16問。残る18問は、価格の計算や非公開情報の保護など、設計上ローカル処理で回答する経路だった。すべての質問に生成AIを使う構成ではない。

## 速度と実画面

| 計測対象 | 中央値 | 範囲 |
|---|---:|---:|
| 60問の処理中イベントが届くまで | 26ms | 11〜99ms |
| OpenAI採用26問の最初の本文イベント | 1.47秒 | 0.22〜3.30秒 |
| OpenAI採用26問の回答完了 | 1.64秒 | 1.07〜3.54秒 |
| 生成後に定型文へ戻った16問の回答完了 | 1.63秒 | 1.40〜4.37秒 |

最初の本文の最短0.22秒は、複合質問で登録情報の定型文が先に出る経路。APIイベント到着の計測であり、文字ごとのブラウザ描画時間ではない。

PlaywrightのChromiumでPC（1440×1000）とスマートフォン相当（390×844）の画面を操作し、「パッキン選定」から「水の配管、材質未定」へ続けて質問した。4回答すべてOpenAIの実回答で、ブラウザ操作からの完了計測は1.59〜2.46秒。回答の途中表示イベントも確認した。

スクリーンショットを確認し、両画面でチャット本文と入力欄が表示されている。横方向のページはみ出し、ブラウザのJavaScript例外は検出なし。この2問の流れではパッキンの話題を維持できた。ただし実スマートフォン端末・通信回線の試験や、全質問の画面検証ではない。

今回の60問では、登録された非公開仕入先社名・HP文字列の出力検知は0件。登録文字列照合と回答内容レビューの結果であり、すべての表現による漏洩防止を保証するものではない。

## 改善が必要な点と原因の確認範囲

1. **既に伝えた製品・用途・数量・希望時期の保持。** 明確な型番を伝えた後でも、翌日配送の質問では商品名を聞き直した。履歴としてAIへ渡すのが直近6メッセージのため、長い相談で初期条件が落ちる構造も確認した。
2. **顧客が入力した数値を復唱・要約できる検証。** 回答の数値チェックが許可するのは登録事実等の数値のみで、質問・履歴の数値は対象外。25A・40度・10個などを正しく復唱した回答まで拒否される可能性がある。各失敗の監査ログは `failed_or_ungrounded` にまとめられており、16件すべての個別原因は断定できない。
3. **要約依頼・条件変更・急ぎ依頼の理解。** 「納期」等の単語だけで振り分け、要約要求に答えないケースがあった。
4. **自然な表記と確保可否の理解。** 「ねだん」「ざいこ」「確保できる？」を適切に扱う必要がある。
5. **担当者への相談手順。** 画面の「担当者に相談」等を具体的に案内し、チャットでの相談と問い合わせ送信済みの状態を明確にする必要がある。
6. **顧客向けの言い方。** 「担当のアプリ」「別のアプリ」という内部実装の説明が実回答に現れた。担当者・相談窓口という自然な案内へ修正する必要がある。

まずTypeSafeの専用キーで接続を確認し、同じ質問を両APIが正常な状態で再試験する。その後、残った不具合を修正し、同じ会話で改善前後を比較する。本試験ではアプリの回答ロジックを変更していないため、改善済みとは報告しない。
